# 数据库结构变更分析（v0.8.8-rc4 → v0.8.8 + upstream/main 最新）

> 分析日期：2026-10-08
> 对比基准：
> - **基准 A**：分支原基线 `c8c5478cf`（package.json 版本 `v0.8.8-rc4`）↔ 官方 0.8.8 发布源码包
>   （`02.code/01.sources/LreChat-0.8.8` 同目录 `LibreChat-0.8.8`，版本 `v0.8.8`）
> - **基准 B（实际合并）**：`c8c5478cf` ↔ `upstream/main@e1dfc1044`（v0.8.8 发布 + 发布后约一周的修复，共 326 个提交）
>
> **本次合并实际采用的是基准 B**（合并提交 `58fcd4479`），因此部署环境应以基准 B 的结论为准。

## 一、总结论

| 项 | 基准 A（→0.8.8 发布包） | 基准 B（→upstream/main 实际合并） |
|---|---|---|
| Schema 文件差异 | **0 个文件**（59 个文件逐一相同） | 19 个文件、+355 行（详见下文） |
| 新集合 | 无 | **2 个**：`passkeys`、`toolapprovalgrants` |
| 删除/重命名字段 | 无 | 无 |
| 数据转换迁移（文档改写） | 不需要 | **不需要**（全部为增量式新增字段） |
| 索引变更 | 无 | **7 组新索引**（启动时自动创建） |
| 必须执行的迁移脚本 | 无 | **无**；条件性维护见第四节 |

**一句话结论：本次升级没有破坏性或转换性的数据库迁移。所有结构变更都是增量式
（新集合、新字段、新索引），在 API 首次启动时由 Mongoose 自动创建；仅当部署库
创建于 v0.8.7 或更早版本时，才需要额外执行一次 `migrate:tenant-indexes`（见第四节）。**

### 3.3 新增索引（7 组，API 启动时自动创建）

| 集合 | 新索引 | 用途 |
|---|---|---|
| agents | `{createdAt:-1,_id:1}`、`{tenantId:1,createdAt:-1,_id:1}` | 新旧排序扫描 |
| conversations | `{user:1,isArchived:1,endpoint:1,updatedAt:-1,_id:-1}` | 端点筛选避免全列表扫描 |
| conversations | `{user:1,updatedAt:-1,_id:-1}` | 默认会话列表 + 30s 未读轮询 |
| files | `{user:1,tenantId:1,context:1,_id:-1}`（命名 `project_file_picker`，partialFilter `embedded:true`） | 项目文件选择器 |
| scheduleruns | `{user:1,tenantId:1,conversationId:1}` | 自动完成准入 |
| shares | `{user:1,conversationId:1}` | 侧栏「已共享」筛选 |
| tokens | `{scope:1}`（**唯一、稀疏**，命名 `unique_token_scope`） | 作用域令牌唯一性 |
| users | `{tenantId:1,'favorites.agentId':1}` | 收藏计数按租户收敛 |

注意：
- `unique_token_scope` 为 **sparse 唯一索引**，只约束存在 `scope` 字段的新文档，与存量数据无冲突。
- 以上索引随 Mongoose `autoIndex` 在 API 启动时自动创建（LibreChat 默认依赖启动建索引；
  若部署设置了 `MONGO_AUTO_INDEX=false`，则通过 `npm run migrate:tenant-indexes` 显式创建，
  该命令会「显式创建当前 schema 的全部索引」，即使 autoIndex 被关闭）。
- 无任何索引被删除或修改键模式（相对 rc4）。

## 四、部署环境数据库更新操作

### 4.1 常规升级（库由 0.8.8-rc 系列创建 —— 本项目部署栈属于此类）

**无需任何迁移脚本。** 流程：

```bash
# 1. 备份（必做）
# 本地开发库（mongod @127.0.0.1:27017，dbpath C:/Users/tonen/.local/var/mongodb）：
mongodump --host 127.0.0.1:27017 --db LibreChat --out ./backup_$(date +%Y%m%d)
# 部署栈（deploy-compose：容器 chat-mongodb，宿主机映射 27018）：
docker exec chat-mongodb mongodump --db LibreChat --archive --out /dev/stdout > ./LibreChat_$(date +%Y%m%d).archive

# 2. 重建并替换 API 镜像（见 02-上游合并指南.md 第 5 节），重启栈
#    新集合（passkeys、toolapprovalgrants）与新索引在 API 首次启动时自动创建

# 3. （可选）验证索引已创建
docker exec chat-mongodb mongosh LibreChat --quiet --eval \
  "db.passkeys.getIndexes(); db.toolapprovalgrants.getIndexes(); db.conversations.getIndexes().filter(i => JSON.stringify(i.key).includes('endpoint'))"
```

### 4.2 条件性维护：库创建于 v0.8.7 或更早 → 必须先做租户索引迁移

症状：升级后 API 日志出现 `Index build failed`（users/roles/presets/accessroles/mcpservers/
agentcategories/messages/conversations 上的旧唯一索引与新的租户复合唯一索引冲突）。

操作顺序（详见仓库根 `UPGRADING.md` 第三节）：

```bash
# 前提：已部署新代码/镜像；源码方式需先 npm run build:packages
# 0. 备份 Mongo，停止所有向库写入的 API 实例（Mongo 保持运行）

# 1. 预览（只读，列出将被删除的过时唯一索引）
npm run migrate:tenant-indexes:dry-run

# 2. 正式执行（幂等，可重跑；失败会保留旧索引不动）
npm run migrate:tenant-indexes

# 3. 退出码为 0 后再启动 API
```

针对本项目部署栈的等价命令（在仓库根目录，直连部署库 27018 端口）：

```bash
# dry-run
MONGO_URI=mongodb://127.0.0.1:27018/LibreChat npm run migrate:tenant-indexes:dry-run
# 应用
MONGO_URI=mongodb://127.0.0.1:27018/LibreChat npm run migrate:tenant-indexes
```

或使用一次性容器（注意 `-w /app`，生产镜像默认工作目录是 /app/api）：

```bash
docker compose -f deploy-compose.yml stop api
docker compose -f deploy-compose.yml run --rm --no-deps -w /app api npm run migrate:tenant-indexes:dry-run
docker compose -f deploy-compose.yml run --rm --no-deps -w /app api npm run migrate:tenant-indexes
docker compose -f deploy-compose.yml up -d api
```

> 本脚本目录下提供了 `check-db.sh` 包装脚本，自动选择 local(27017)/deploy(27018) 目标执行 dry-run。

### 4.3 配套的行为/配置注意项（非数据库，但升级时必须知晓）

1. **Web 搜索权限语义变化**（`UPGRADING.md` 第一节，v0.8.8-rc3 起）：`WEB_SEARCH.USE`
   同时授权外部搜索管线与提供商原生搜索；`interface.webSearch: false` 会把 USER/ADMIN
   的该权限持久化为拒绝，**删除 YAML 字段不会恢复默认授权**（需显式设 `true` 并重启，
   或在权限编辑器中调整）。若启用原生搜索，需按 UPGRADING.md 合并示例配置。
2. **Redis 流式增量默认 25ms 合并**（`UPGRADING.md` 第二节）：未设置
   `STREAM_DELTA_COALESCE_MS` 时默认启用；设为 `0` 恢复逐增量发布。多版本混布期间
   注意生产者/消费者兼容矩阵。
3. 建议部署时显式确认 `.env` 中 `MONGO_AUTO_INDEX`/`MONGO_AUTO_CREATE` 的取值
   （留空 = Mongoose 默认自动建索引；本项目未自定义则无需改动）。
